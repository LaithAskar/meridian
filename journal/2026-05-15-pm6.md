## Explanation

**Sharpe formula**: `mean / std(ddof=1) * sqrt(252)` exactly matches DESIGN.md's locked spec. `ddof=1` (sample std) is standard for backtests — we have a sample of days, not the population. The `std == 0.0` guard catches only exact float zeros; constant non-zero returns produce a tiny but non-zero std due to IEEE 754 representation (e.g., `0.001 * 100 ≠ 0.001` sum exactly), so no artificial zeroing is applied there — the correct answer for truly constant returns is a very large Sharpe, and the guard only prevents the division-by-zero case from all-zero returns.

**Sharpe SE**: The Mertens / Lo (2002) formula `sqrt((1 + SR²/2) / n)` is the standard quant-finance approximation for iid daily returns. It lets you say "pre-COVID Sharpe 1.2 ± 0.35, post-COVID Sharpe 0.9 ± 0.28 — not statistically distinguishable." The true SE is wider if returns are autocorrelated (momentum strategies especially), but this approximation is the interview-standard convention and is correctly documented in the module docstring.

**Max drawdown sign**: Returned as a positive magnitude (0.25 = 25% drawdown). This is cleaner for summary tables than a negative value. The raw series minimum is always ≤ 0; we negate it. `cummax()` is O(n) and produces the exact running-peak series needed for daily-bar drawdown; no sorting or secondary passes needed.

**Hit rate**: `pnl > 0` explicitly excludes breakeven trades (pnl == 0). This matches financial industry convention — a breakeven trade is not a win.

**avg_win_loss**: Returns `nan` (not 0.0 or exception) for undefined quantities (no wins, no losses, or no trades). `nan` is the correct sentinel here: it propagates predictably in pandas, shows up clearly in summary tables, and avoids false-zero confusion (a 0 win/loss ratio means something, nan means "not computable").

**Exposure**: Binary in-market / out-of-market per day (`num_positions > 0`). A strategy with 5 simultaneous positions counts that day as "in market" the same as one with 1 position. This is the standard definition for long-only strategies. More granular exposure (e.g., sum of position weights / NAV) is deferred as out of scope per DESIGN.md.

**CAGR**: Uses the passed-in `years` parameter rather than inferring from the DatetimeIndex length. This is intentional: the caller knows the window (14.0 for the full 2010-2024 run, ~10.17 for pre-COVID, ~4.83 for post-COVID). Deriving years from trading days would require a calendar convention and is more fragile.

**total_return**: Raises `ValueError` on empty or zero-initial equity rather than returning 0.0 or nan. This is a contract violation (the engine always initialises to a positive cash amount) and a hard error is the right response.

**Alternatives rejected**:
- Vectorised `numba` or C extension: overkill for 14 years × 1 daily computation. Pure pandas is readable and fast enough.
- `scipy.stats.sharpe_ratio`: not in this repo's dependency set and doesn't add the SE calculation.
- Negative max_drawdown (some libraries use -0.25): positive is unambiguous in table context.
