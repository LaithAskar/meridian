### `backtest/tests/test_export_html.py` — add `_require_notebook_env()` guard

The existing guard was `pytest.importorskip("nbconvert")`. That correctly skips
tests when nbconvert is absent. But it doesn't guard against the case where
nbconvert IS installed but no Jupyter kernel spec is registered — which is the
state of a fresh cloud container where `pip install nbconvert` succeeds (it's
in `requirements.txt`) but `python -m ipykernel install --user` has never been
run.

In that state, the class-scoped fixture and three standalone tests in
`TestExportIntegration` try to execute the notebook, reach the nbclient kernel
launch step, and crash with `jupyter_client.kernelspec.NoSuchKernel: No such
kernel named python3`.  This surfaces as 3 FAILED + 9 ERROR (the fixture errors
cascade to all 9 fixture-dependent tests).

**Fix:** new helper `_require_notebook_env()` that does both checks in sequence:

```python
def _require_notebook_env(reason: str = "") -> None:
    pytest.importorskip("nbconvert", reason="nbconvert not installed")
    try:
        from jupyter_client.kernelspec import KernelSpecManager
        KernelSpecManager().get_kernel_spec("python3")
    except Exception:
        pytest.skip(
            "python3 kernel spec not registered; "
            "run: python -m ipykernel install --user --name python3"
            + (f" ({reason})" if reason else "")
        )
```

All four call sites (`exported_html` fixture + `test_show_input_includes_code`,
`test_custom_output_path_respected`, `test_return_value_equals_output_path`)
now call `_require_notebook_env()` instead of `pytest.importorskip("nbconvert")`.

```diff
-    pytest.importorskip("nbconvert", reason="nbconvert not installed")
+    _require_notebook_env()
```

## Explanation

### Why `importorskip` was not enough

`pytest.importorskip("nbconvert")` raises `Skipped` if `import nbconvert`
raises `ImportError`.  It does not help if nbconvert imports fine but a later
runtime call fails with a non-import exception.  `NoSuchKernel` is raised deep
inside `nbclient` during kernel startup — completely separate from the import
path.  The test needs to check kernel availability explicitly.

### Why check for "python3" specifically

The notebook's kernel name is `"python3"` (set in `results.ipynb`'s
`kernelspec` metadata).  That's the name nbclient uses when starting the
kernel.  Checking for any-kernel-exists would be too loose; checking for
exactly `"python3"` mirrors what nbclient will actually look up.

### Why a function rather than a module-level fixture or mark

A module-level `pytest.mark.skipif` would require evaluating `_has_kernel()` at
collection time, which runs KernelSpecManager on import — fine but slightly
heavier.  A function called at test entry time is idiomatic for "skip if
precondition fails" patterns and avoids any collection-time side effects.
It also makes the skip message testable (verified by calling `_require_notebook_env`
with the kernel manager patched to raise — see the manual verification below).

### Why not fix the kernel registration in requirements.txt or a setup step

`pip install ipykernel` installs the package but does NOT register the kernel
spec.  That requires a separate `python -m ipykernel install --user` invocation.
The right place for that is a session-start hook (Claude Code web hooks), not
requirements.txt.  A robust test is better than an installation pre-requisite
that's easy to forget.
