## Explanation

### Why origin/main was already current

The pm5 run pushed from detached HEAD using `git push -u origin main` with an
explicit refspec. git doesn't require a branch checkout to push — it happily
pushes the detached HEAD's commit chain to the named remote ref. So the 13
accumulated commits reached `origin/main` even though the local `main` pointer
never moved.

The detached HEAD problem is therefore a **local branch pointer drift**, not a
lost-work problem. The push succeeds; `git checkout main` then shows a stale
local branch. The fix is always the same: `git merge --ff-only <detached-tip>`.

### Root cause of recurring detached HEAD

The cloud container clones the repo fresh each session and checks out the
default branch. If the git remote reports the default branch as `HEAD ->
main`, the clone lands on `main` correctly. But the container apparently
initializes with `HEAD` pointing directly at the commit SHA rather than the
branch ref — possibly a shallow-clone or detach-on-clone behavior in the
container orchestration. This is a container infrastructure issue, not a git
repo issue.

**How to fix permanently:** Add a `SessionStart` hook in `.claude/settings.json`
that runs `git checkout main` before any session work begins. This is a
one-line fix Laith can apply. Until then, each routine run's first action
should be the manual recovery above (which takes seconds).
