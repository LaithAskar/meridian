## Explanation

### Why update the existing README rather than create `backtest/README.md`?

The top-level README is the first file a recruiter or interviewer reads. The backtester is the most technically rigorous artifact in the repo — it's the one thing that transforms Meridian from a hobby project with undisclosed risk to a project with a measurable edge claim. Burying it in a subdirectory README means it gets missed.

The existing README already had an honest disclaimer about lacking backtests. Updating that disclaimer to point at the in-progress backtester is more accurate and more compelling than leaving a stale "no backtests" claim.

### Why document methodology before results exist?

Because methodology is the hard part to get right, and results don't validate themselves — methodology does. A reader who understands the universe construction, fill model, and honest disclosures can evaluate whether the eventual numbers are trustworthy. A table of Sharpe ratios without a methodology section is useless.

More practically: 3.1 is blocked on network access, which is an environment configuration issue, not a code issue. The methodology is frozen in DESIGN.md and fully implemented. Documenting it now means Laith can show the README immediately, even before numbers are ready.

### Design choices in the README

**Fill model rationale explicitly stated.** "Close-price fills are amateurish" is in the README because it's the single most common backtesting mistake and the clearest signal that a quant candidate understands market microstructure. If an interviewer asks "why next-bar-open?" the answer is in the file.

**Sharpe SE included.** The standard error formula (`√((1 + S²/2) / n)`) is spelled out because it's what makes regime-split comparisons statistically meaningful. Without SE, saying "Sharpe was 0.8 pre-COVID and 0.5 post-COVID" is just noise; with SE you can say whether the difference is significant.

**Blockers listed in the README, not hidden.** A methodology section that says "VADER and FinBERT results available" when they're blocked would be dishonest. The blockers section is candid about what's pending Laith's decision and why.

**Honest disclosures verbatim.** DESIGN.md §"Honest disclosures" was reproduced verbatim (not paraphrased) so the README is a standalone document. An interviewer reading only the README gets the full picture without needing to open DESIGN.md.

**No invented results.** Since 3.1 is blocked on network access, there are no Sharpe numbers yet. The status table and "Results are not yet available" callout make this explicit. Inventing plausible numbers would be worse than having none.
