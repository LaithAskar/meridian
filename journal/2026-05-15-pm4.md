## Code

### `backtest/fills.py` (new file)

```python
SLIPPAGE_BPS: float = 5.0   # module-level constant; override in tests/sensitivity runs

@dataclass
class Fill:
    ts: datetime
    symbol: str
    side: Literal["buy", "sell"]
    qty: float
    fill_price: float

def fill_order(order: Order, next_bar: pd.Series | None, ts: datetime) -> Fill | None:
    if next_bar is None:
        return None
    open_price = float(next_bar["open"])
    slip = SLIPPAGE_BPS * 1e-4
    fill_price = open_price * (1.0 + slip) if order.side == "buy" else open_price * (1.0 - slip)
    return Fill(ts=ts, symbol=order.symbol, side=order.side, qty=order.qty, fill_price=fill_price)
```

## Explanation

### What the algorithm does

`fill_order` encodes two things:

1. **Next-bar-open execution**: the signal fires at bar *t* close; the fill
   happens at bar *t+1* open.  This models the latency between "I decide to
   trade" and "the market opens tomorrow."

2. **5 bps adverse slippage**: buyers pay `open × 1.0005`; sellers receive
   `open × 0.9995`.  The asymmetry is intentional — slippage is always *against*
   the trader, never in their favour.  This models bid/ask spread and market
   impact in a single number.

### Why this approach

The 5 bps convention is standard for liquid large-cap daily-bar backtests.
At 2010-era spreads on S&P 100 names, 2-4 bps was typical; 5 bps adds a small
margin for market impact, giving a conservatively honest simulation without
requiring intraday tick data.

The `SLIPPAGE_BPS` constant is module-level (not hardcoded) for two reasons:
- Tests can assert on it symbolically (`open * (1 + SLIPPAGE_BPS * 1e-4)`) rather
  than magic numbers, so a future sensitivity run that changes the constant keeps
  all tests valid.
- A Phase 4 sensitivity sweep can `monkeypatch` it without modifying `fills.py`.

### Gap handling

Gap-up / gap-down opens are used as-is.  There is no "fair value" reconstruction
because: (a) the strategy's prior-close signal already captured the gap as a cost,
and (b) we don't have intraday data to simulate where inside the gap we would have
filled.  Using the open price is the most conservative and auditable choice.

### Delisted / missing bar

Returning `None` rather than raising an exception keeps the engine simple: it
can do a null check and record a cancellation without try/except boilerplate.
This also correctly models the real-world case where a position in a soon-to-delist
name simply can't be added; the strategy is not charged.

### Alternatives rejected

- **Close-price fills** — explicitly prohibited by DESIGN.md ("Close-price fills
  are amateurish").  Would give unrealistic performance because the signal and
  fill price are from the same bar.
- **Partial fills** — unnecessary for this universe (S&P 100 large-caps, small
  position sizes ≈ 1% NAV).  Adds complexity without accuracy.
- **Separate slippage + commission model** — DESIGN.md specifies $0 commission
  (post-2019 broker convention) and a single 5 bps slippage number.  Decomposing
  it further is out of scope.
