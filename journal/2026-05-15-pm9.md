## Explanation

### QuantStrategy history cap

The signal functions (`momentum_signals`, `mean_reversion_signals`) are called at every bar and receive the full accumulated OHLCV history for all symbols. Without a cap, by bar 3 528 (end of 14-year window) they would process DataFrames with 3 528 rows each — making total per-run compute O(T²×N) ≈ O(3 528² × 100) ≈ 1.2 billion operations. Capping at 300 rows makes it O(T×N×300) ≈ O(3 528 × 100 × 300) ≈ 105 million, roughly a 12× speedup. The signal quality is unchanged:

- **12-month momentum return** uses `close.iloc[-252]` and `close.iloc[-1]` — correct at 300 bars.
- **EMA(12), EMA(26)** converge after 3× span ≈ 36–78 bars — correct at 300 bars.
- **RSI(14)** converges after 3×14 = 42 bars — correct.
- **Bollinger Band(20)** needs 20 bars — correct.

The 300-bar cap is a valid, semantically-neutral optimisation. It would only matter if a signal used `iloc[0]` for a 15-year lookback, which none of them do.

### run_quant.py architecture

The runner is structured as a library (`run_quant_backtest(...)`) rather than a script so tests can call it directly. The CLI (`if __name__ == "__main__"`) is a thin wrapper over the library call. This follows the same testability pattern as `fetch_bars` in `data.py`.

Regime splits are handled by `slice_window`: the engine runs once over the full window (not twice), and the pre/post-COVID views are sliced from the single result. This is correct because the equity curve is a continuous process — positions from before the split still appear as open at the split date, and the regime slice is just a window into the same trajectory. Trades are sliced by `exit_ts`, not `entry_ts`, which correctly assigns each trade's P&L to the period where it was realised.

`_nan_to_none` ensures the metrics dict is always JSON-serialisable. Python's `json.dumps` raises `ValueError` on `float('nan')` and `float('inf')`. The trading metrics module returns NaN for "no trades" cases, so this conversion is essential.

### Why no `json.dumps` with a custom encoder?

A `default=lambda x: None if math.isnan(x) else x` encoder on `json.dumps` would be an alternative, but it would silently discard NaN without surfacing the None in the dict returned to callers. Explicit NaN→None before the call makes the conversion visible and testable.
