## Explanation

### Why import rather than copy signal logic

`momentum_signals` and `mean_reversion_signals` are **pure pandas functions** — they
take a `dict[str, DataFrame]` and produce lists of score dicts. No network I/O, no
caches, no broker references. They're imported directly.

`detect_regime()` is different: it calls `yfinance.Ticker("^VIX").history(...)` and
`yfinance.Ticker("SPY")...` live, wrapped in a `@TTLCache(ttl=300)`. Using it in a
backtest would inject current-day prices as 2010-era "regime" signals — pure look-ahead
bias. The five-regime logic (VIX thresholds + SPY SMA50/SMA200 crosses) was replicated
in `_regime_at()`, which reads from `pd.Series` objects passed at construction.

### History buffer

`on_bar` receives one bar per symbol per call. The strategy needs rolling history
(momentum requires 252 bars for a full 12m signal; mean-reversion needs 30+). The
buffer is `dict[str, list[dict]]` accumulating from day 1. Keys are capitalised
(`"Close"`, `"Open"`, etc.) to match the backend functions' `df["Close"]` convention.

The `universe_data` dict is rebuilt from the full buffer on every bar. This is O(n ×
history_len) per call — not ideal for a 100-symbol × 3,500-day full run, but clear
and correct. For Phase 3 performance we can investigate reusing the previous
DataFrame and appending; deferred for now.

### Position sizing

Equal-weight: `target_per_slot = equity / max_positions`. Shares = `floor(target /
price)`. A `virtual_cash` counter tracks buying power across concurrent buys in the
same bar to avoid overdrafting. Sells always exit the full position.

Positions are held until `aggregate_signals` returns `direction="sell"` for that
ticker. No time-based exit, no trailing stop — by design (DESIGN.md: backtester
measures raw edge; risk management is a layer above).

### Factor weight = 0

`factor_signals=[]` is passed to `aggregate_signals` and `"factor": 0.0` in every
regime weight dict. The aggregator normalises by total contributing weight, so passing
an empty factor list with weight zero correctly excludes factor from the ensemble score
without diluting momentum or mean-reversion weights.

### RSI edge case discovered in testing

`compute_rsi` uses `fillna(50)` to handle division-by-zero when all recent moves are
gains (or all losses). For a pure monotone exponential series, every delta is positive,
`loss_mean = 0`, `gain/loss → NaN → 50`. RSI is always 50, so the RSI branches of
`mean_reversion_signals` never fire.

The original `test_parabolic_rally_produces_sell` used `100 × 1.04^i` — this failed
because: (1) RSI = 50, (2) Bollinger Bands expand proportionally with the exponential
trend, keeping the current price within the bands. Fix: use a **flat-then-spike** series
(55 flat bars at 100 then 5 bars at +20%/bar ≈ price 249). This produces z-score ≈ 3.1
(price 3σ above the 20-bar mean) and pushes price above the BB upper band, yielding
score = −0.55. This is also a more honest test — it checks the condition that mean
reversion is actually designed to detect: "price is statistically extreme relative to
recent trading range."
