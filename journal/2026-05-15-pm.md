## Explanation

**Why per-symbol parquet files rather than one big file?**
Each symbol's cache is ~3 500 rows (14 years × 252 trading days). A single file for 100 symbols would be 350 k rows — still small, but it forces a full re-fetch of all 100 symbols whenever any one symbol's range is stale. Per-symbol files allow the common case (95 symbols cached, 5 new) to incur only 5 network fetches instead of 100.

**Why `threads=False` + 0.2 s pause rather than bulk `yf.download(list)`?**
The bulk download returns one wide DataFrame that still has to be split per symbol before writing to individual cache files — net code complexity is the same, but per-symbol downloads map cleanly to per-symbol cache files with no split step. The 0.2 s pause targets Yahoo's informal ~5/sec rate limit; the single retry-on-empty handles transient 429-style rejections that yfinance 1.x signals by returning an empty DataFrame rather than raising an exception.

**Why monkeypatch `yf.download` rather than `_download_symbol`?**
Patching at the `yf.download` level exercises the full normalization pipeline (MultiIndex column flatten, lowercase rename, tz-naive conversion) under the mock. The mock returns the actual yfinance 1.3.0 output shape, so if a future yfinance release changes its column structure a test will break at the right seam.

**Why tz-naive index for daily bars?**
Daily bars have no intraday component — the date is the complete key. Storing UTC timestamps for daily data creates friction when comparing with `date` objects in loop code. The old Alpaca module used UTC; the new module uses tz-naive DatetimeIndex, which is the pandas convention for daily financial data (e.g., `pd.bdate_range` is tz-naive by default).

**Why `auto_adjust=True`?**
DESIGN.md requires total-return semantics for apples-to-apples comparison with SPY. `auto_adjust=True` bakes splits and dividends into OHLC prices so a long hold through a 2-for-1 split doesn't appear as a -50% return overnight.

**Alternative rejected: `yf.Ticker(sym).history(...)`**
More idiomatic for single-symbol use, but the TODO explicitly required `yf.download`. Both ultimately call the same Yahoo endpoint and return the same data; `download` is the more widely used path in the yfinance ecosystem.
