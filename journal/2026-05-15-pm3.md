### `backtest/strategy.py` (new file)

```python
@dataclass
class Order:
    symbol: str
    side: Literal["buy", "sell"]
    qty: float
    order_type: str = "market_next_open"
    # __post_init__ validates qty > 0 and side in {"buy","sell"}

@dataclass
class Position:
    symbol: str
    qty: float
    avg_cost: float
    # .market_value property = qty * avg_cost

@dataclass
class Portfolio:
    cash: float
    positions: dict[str, Position] = field(default_factory=dict)
    # .equity(prices=None) — marks to market if prices supplied, else uses avg_cost
    # .num_positions — count of positions with qty != 0

class Strategy(ABC):
    def __init__(self, max_positions: int = 10) -> None: ...
    @abstractmethod
    def on_bar(self, ts: datetime, bars: dict[str, pd.Series], portfolio: Portfolio) -> list[Order]: ...
```

### `backtest/tests/test_strategy.py` (new file, 20 tests)

Covers:
- `Order`: valid buy/sell, custom order_type, `qty <= 0` raises, bad side raises
- `Position`: `market_value` arithmetic
- `Portfolio`: equity with no positions, avg_cost fallback, mark-to-market, partial

- `Strategy`: NoopStrategy subclass, `max_positions` default, `on_bar` return type,
  portfolio identity passed through, abstract class cannot be instantiated directly

## Explanation

**Design choices:**

`Order` is a dataclass with a `__post_init__` guard rather than a NamedTuple.
Dataclasses allow default field values (the `order_type` default) without the
boilerplate of a custom `__new__`; NamedTuples with defaults work but feel awkward
for mutable-ish domain objects. The guard is in `__post_init__` rather than a
factory function so the invariant is attached to the type itself — any code path
that constructs an `Order` (including deserialization) gets validation for free.

`Portfolio.equity()` accepts an optional `prices` dict rather than requiring a
full mark-to-market at every call site. The fallback to `avg_cost` is intentional:
when the engine snapshots state between bar calls, it may not have a fresh close
price for every position (e.g., a just-added position whose fill happened this bar).
Partial coverage is handled gracefully — missing symbols fall back to cost basis.

`Strategy` is an ABC rather than a Protocol because the engine needs to call
`strategy.max_positions` as a base-class attribute, and ABCs enforce the contract
at instantiation time (`TypeError: Can't instantiate abstract class`) rather than
silently at call time. The `max_positions` enforcement contract lives in the
*strategy*, not the engine — consistent with DESIGN.md's "raw signal edge" goal;
the engine is kept dumb.

**Alternatives rejected:**

- `@dataclass(frozen=True)` on `Portfolio`: portfolio state is mutated in-place by
  the engine's fill loop, so immutability would require copying the whole struct on
  every fill — wasteful for a 3 650-bar × 100-symbol backtest.
- Putting `equity()` logic in the engine: mixing accounting into the engine makes
  it harder to test the equity calculation in isolation. Keeping it on `Portfolio`
  means the tests can assert exact numbers without spinning up an engine.
