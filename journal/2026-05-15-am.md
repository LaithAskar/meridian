## Explanation

### What the module does

`fetch_bars` is the single entry point for market data throughout the backtester. It returns a `pd.DataFrame` with a two-level index `(symbol, timestamp)` and columns `open, high, low, close, volume, trade_count, vwap` — the same shape the Alpaca `BarSet.df` property produces natively, so the engine can slice by symbol with `df.xs(sym, level="symbol")` without reshaping.

### Cache strategy

Each symbol gets one parquet file per timeframe: `data/cache/AAPL_1Hour.parquet`. On every call, `_cache_covers` reads the file header to check whether the stored index spans `[start, end]`. If yes, the file is read and filtered in-process — no network call. If no (or the file is absent), the whole window is re-fetched from Alpaca and the cache is replaced.

This is intentionally simple — no range merging, no partial update. The reasoning: the bulk-download script (task 0.3) will pull the full 2016–2024 window once per symbol. After that, every backtest run is a pure cache hit. The added complexity of merge logic buys nothing for this workflow.

### Why per-symbol files, not one big parquet?

A single `all_symbols.parquet` for 100 tickers × 9 years × hourly bars ≈ 1.5 M rows × 100 ≈ 150 M rows. That's fine for columnar reads, but partial updates (adding one symbol after a gap) require rewriting the whole file. Per-symbol files make it trivial to re-fetch a single bad ticker without touching the others.

### Credential handling

Credentials live in `ALPACA_API_KEY` / `ALPACA_SECRET_KEY` env vars, read at call time by `_make_client()`. The client is injected as a parameter (`client=`) so tests can pass a mock without touching the environment. This is the standard dependency-injection pattern for code that calls external services.

`alpaca-py` was missing from `requirements.txt` — added it along with `pyarrow` (parquet engine) and `pytest`.

### Timestamp normalization

pyarrow round-trips timestamps at millisecond precision; pandas `date_range` defaults to second precision. Without normalization, the cache-hit and cache-miss paths return different `datetime64` dtypes — breaking exact equality checks and potentially causing subtle filter bugs. `fetch_bars` casts the timestamp index level to microseconds on every return path, giving a single consistent dtype regardless of origin.

### Bugs caught during testing

1. `_cache_covers` originally called `pd.read_parquet(path, columns=[])`. An empty columns list makes `df.empty == True` even for a file with rows, because pandas treats a zero-column DataFrame as empty. Fixed to `pd.read_parquet(path)` (no column restriction).
2. `datetime64[s, UTC]` vs `datetime64[ms, UTC]` mismatch after parquet round-trip. Fixed by normalizing to `us` resolution before returning.

### Alternatives rejected

- **yfinance as data source**: already in requirements but IEX-via-Alpaca is the locked design choice (free tier, official market data, no terms-of-service ambiguity for backtesting).
- **SQLite cache instead of parquet**: columnar reads on parquet are ~10× faster for time-range scans; SQLite has no columnar advantage and adds a dependency.
- **Range merging in cache**: YAGNI. The bulk-download script fetches once; no use case for partial range extension in normal backtester operation.
