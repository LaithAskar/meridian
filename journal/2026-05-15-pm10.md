## Explanation

### Why extract logic into nb_utils.py?

Jupyter notebooks are not unit-testable directly: every test that touches a `.ipynb` file requires spawning a kernel, which is slow, fragile, and environment-dependent. By separating the data-loading, transformation, and formatting logic into `nb_utils.py`, all the meaningful code can be covered by fast, deterministic pytest tests. The notebook itself becomes a thin presentation layer — it calls the library and calls `plt.show()`.

This is the standard quant-research pattern: a `utils.py` (or `analytics.py`) module paired with a notebook. The notebook is the report; the module is the engine.

### Why a builder script instead of hand-editing JSON?

The `.ipynb` format is JSON with multi-line strings represented as lists-of-lines. Hand-editing that is error-prone and produces large diffs. The `_build_notebook.py` script keeps each cell as a readable Python string, regenerates the notebook in one command, and makes future edits (reordering sections, adding cells) straightforward. The `results.ipynb` file in the repo is always the canonical artifact; the builder script is how it was produced.

### Graceful degradation design

The notebook works in three states:

1. **No results at all** (current state — 3.1 blocked on network, 2.2/2.3 blocked on news data): all charts render empty with "No results yet" annotations; the metrics table shows '—' for every cell. The notebook is still openable and navigable.

2. **Quant only** (after 3.1 unblocks via local data cache or network access): equity curve, drawdown, regime split, and trade statistics all render for the quant strategy. SPY benchmark line appears if `spy_curve.csv` is present. VADER and FinBERT columns show '—'.

3. **All three strategies** (after 2.4 resolves and 3.2/3.3 run): full comparison view with all overlays.

### normalise_equity design choice

Rebasing to 100 (not to the actual initial cash of $1M) is the right choice for an interview-facing chart. A chart with y-axis at 1,000,000–1,350,000 is hard to read; a chart with 100–135 immediately communicates "35% gain" without arithmetic. The relative shape of every series is unchanged.

### compute_drawdown_series sign convention

Returns values ≤ 0 (peak-to-trough as a negative fraction), matching the finance convention for drawdown in intermediate calculations. The notebook multiplies by 100 before plotting and uses `fill_between(..., 0)` so the chart shows a downward filled area, which is visually intuitive. The metrics module's `max_drawdown()` already returns a positive magnitude — these two are consistent by design.

### format_metric_val and METRIC_FORMATS

Using Python's `format()` built-in with format strings (`.3f`, `.1%`, `,.0f`) rather than f-strings or string templates keeps the formatting rules in one testable dict. The `%` format strings handle the ×100 automatically — `format(0.12, ".1%")` → `"12.0%"` — so callers never need to multiply before calling `format_metric_val`.
