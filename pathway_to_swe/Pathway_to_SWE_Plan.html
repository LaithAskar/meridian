1. Studying Method — The Improved Work Block

What was missing

  1. Spaced repetition. Single sessions don't encode long-term. Review at ~1d, ~3d, ~7d, ~30d or you forget the majority within two weeks.
  2. Interleaving. Mixing problem types within sessions builds the discrimination skill that matters in real interviews.
  3. Active retrieval > passive consumption. Watching NeetCode videos is mostly wasted time. Solve unaided first.
  4. Calibration. Predict confidence before checking the answer. Builds metacognition — knowing when you don't know.
  5. Pre-sleep review. 10 min on the day's hardest concept right before bed boosts consolidation.
  6. Micro-breaks. 60 min uninterrupted is past most people's deep-focus ceiling.

3. The Replacement Project — Tachyon

Working name: tachyon — the hypothetical particle that exceeds light speed. Fits the sub-microsecond latency target. Short, distinctive, defensible in interview.

Alternates if you don't like it: orderbook-engine (boring but explicit), meridian-matcher (ties into existing brand).

What it is

A limit order book matching engine in C++17. Maintains bids/asks, accepts limit/market/cancel orders, matches them by price-time priority, emits trade reports. Deployed as a service with a benchmark harness measuring throughput and latency percentiles.

Why this project

  • Pure quant signal. Citadel Securities, Jane Street, HRT, Optiver, IMC use matching-engine implementation as interview questions. You walk in having already built one.
  • Forces real C++. Your resume claims it. This proves it.
  • Real data structures. Sorted price levels (RB-tree / std::map), per-level deques, lock-free queues. This is the systems-DS work that interviewers care about.
  • Performance is measurable. "1M orders/sec, p99 12µs" is a portfolio bullet that punches above its weight.
  • Differentiates. Every undergrad has trained an ML trading model. Few have built exchange infrastructure.
  • Scoped. 3–4 weeks at your pace if you stay disciplined.

Stretch goals (not required)

  • FIX protocol order entry parser
  • WebSocket-based live order book viewer (reuses your Next.js chops)
  • Wire into Meridian as simulation backend — strengthens both projects with one effort
  • Lock-free SPSC queue for ingestion
  • Event-sourcing persistence + replay

Reading list before you write code

  • Larry Harris — Trading and Exchanges, ch. 6–9 (order book mechanics)
  • QuantCup matching engine challenge — open-source reference implementations
  • Optiver / IMC / Jane Street public talks on exchange architecture (YouTube)

Resume bullet target after build
